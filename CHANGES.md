# Зміни в TUMBA NOTES (ревізія 11.11.2026)

Огляд: пройшовся по всьому коду (40 Kotlin-файлів), знайшов і виправив помилки, які втрачали
дані або ламали основний сценарій «нотатки + папки». Зайве — прибрав.

## Виправлені помилки, що втрачали або псували дані

1. **Редактор воскрешав видалені нотатки.** `DisposableEffect` зберігав ноту під час виходу з
   екрана завжди — навіть якщо її щойно стерли назавжди, вона записувалась у базу назад.
   Прибрано; збереження тепер відбувається явно (кнопка «назад», дії в меню, автосейв).
2. **Нотатку неможливо було очистити.** Порожній текст замінювався старим вмістом через
   `ifBlank { note.content }`. Тепер `null` означає «редактор ще не готовий», а `""` — реальне
   значення (`getContentOrNull()`).
3. **Зміна кольору/папки зберігала застарілий текст.** Зберігалось `note.copy(...)` зі старим
   вмістом, тож останні набрані символи (до 800 мс) губились. Тепер зберігається `currentNoteState()`.
4. **Перехід між нотатками всередині редактора показував попередню нотатку.** Текст вантажився
   лише в `factory` AndroidView. Тепер редактор перестворюється на кожен `note.id` (`key(note.id)`
   + стан, прив'язаний до нотатки).
5. **Фільтр по тегу не оновлювався.** У `remember(...)` не було `noteTagsMap` — список лишався
   старим після зміни тегів.
6. **Відновлення бекапу в режимі «replace» могло писати поза транзакцією.** `saveSetting()` і
   `clearAllData()` перемикали диспетчер всередині `withTransaction`. Тепер налаштування
   пишуться напряму через DAO всередині тієї ж транзакції.
7. **Імпорт JSON звітував про успіх навіть при помилці.** Діалог чекав синхронний `Result`, а
   імпорт асинхронний → завжди «success». Перероблено на callback.
8. **Вставка JSON у режимі «replace» знищувала базу без підтвердження** (у файлового імпорту
   попередження було). Тепер попередження спільне для обох шляхів.
9. **Дублікат нотатки втрачав теги** (лежав мертвий код `existingTags`). Тепер теги копіюються.
10. **Видалення папки було нетранзакційним** — тепер нотатки й папки змінюються атомарно.
11. **Цикл папок.** Можна було зробити папку вкладеною у власного онука — така гілка зникала з
    дерева. Прибрано зі списку батьківських усіх нащадків.
12. **Експорт бекапу не містив історії редакцій** — тепер містить (`allRevisions`).

## Виправлені помилки, що ламали інтерфейс

13. Порожній екран редактора, якщо нотатку видалили з-під нього: додано `BackHandler` і кнопку
    «Назад» (раніше з екрана не було виходу).
14. Кнопка «Очистити кошик» була недосяжна: колбек `onEmptyTrash` передавався, але ніде не
    викликався. Додано дію в екрані кошика.
15. **Мертва смуга між панеллю редактора і клавіатурою.** `Scaffold` додавав відступ під
    навігаційну панель (48dp), а редактор ще раз додавав `imePadding()` на всю висоту клавіатури,
    тому панель форматування висіла на 48dp вище клавіатури. Додано
    `Modifier.consumeWindowInsets(innerPadding)`: тепер `imePadding()` враховує вже зайнятий
    відступ і панель притискається до клавіатури.
15. Після «Очистити всі дані» виставлявся неіснуючий режим `"dashboard"` — тепер `"list"`.
16. Екран `DashboardScreen` був недосяжним (режим ніколи не вмикався) — видалено разом із гілкою.
17. Тап по чек-боксу перемикав рядок під курсором, а не той, по якому тапнули — тепер передається
    позиція рядка.
18. Лічильники слів/символів показували збережений, а не поточний текст.
19. Прев'ю нотатки в картці показувало сиру розмітку (`##`, `**`, `[[...]]`) — тепер чистий текст.
20. Після видалення папки/тегу, які були відкриті, список лишався відфільтрованим по неіснуючому
    id — тепер вибір скидається.
21. `highlightSubstring` у пошуку міг кинути `StringIndexOutOfBoundsException` (індекси з
    `lowercase()` не збігаються з оригіналом) — додано перевірки меж.
22. Вікно історії редакцій було порожнім, поки не тапнеш рядок: обрана редакція тепер
    підставляється, коли дані довантажуються.
23. Аналітика рахувала архівні нотатки «активними» — тепер як усюди: не в кошику й не в архіві.
24. Сортування не зберігалось: `defaultSort` у налаштуваннях існував, але ігнорувався. Тепер
    список відкривається з обраним порядком, а вибір у меню запам'ятовується.
25. Ліміт історії редакцій (`historyRetentionCount`) не діяв — було жорстко 25.

27. Перемикач `isUpdatingInternally` у редакторі нарешті використовується (не було жодного читання).
28. Дублікати в історії пошуку: тепер один запис на запит + обрізання до 20.
29. Прибрано 6 невикористаних мережевих/AI-залежностей (`firebase-ai`, `firebase-appcheck`,
    `retrofit`, `okhttp`, `moshi`, `logging-interceptor`), плагіни `google-services` і `secrets`.
    Застосунок повністю офлайн — жоден із цих пакетів не використовувався в коді.
    Разом з ними пішли `.env.example`, `googleServices.missing.passthrough` і вимога
    `GEMINI_API_KEY` з README (вона була неправдивою).
30. README та `metadata.json` приведено у відповідність до реального стану проєкту.

## Головна сторінка: папки списком + нотатки квадратиками

Екран «Усі нотатки» без фільтрів тепер виглядає як стрічка:

- зверху **список папок** з відступами для вкладеності, кольором теки та кількістю нотаток;
  показується до 8 тек, далі — кнопка «Всі папки», що відкриває повний екран папок;
- під ними — **нотатки квадратними плитками** у дві колонки (співвідношення сторін 1:1):
  заголовок, прев'ю без розмітки, зірочка, позначка шпильки (тап по ній знімає шпильку), дата;
- закріплені нотатки, як і раніше, йдуть першими.

Фільтри (папка, тег, пошук, архів, кошик) працюють як раніше — там показується звичний
список або сітка. Нових рядків у `TumbaStrings` не додано: використані наявні ключі
(`folders`, `viewAll`, `recentNotes`, `notesCountSuffix`, `noFoldersYet`, `noNotesYet`).

## Що варто зробити далі (не робив, щоб не ламати збірку навмання)

- **Підтвердження перед видаленням вкладення** — зараз файл з диска видаляється одразу
  (`AttachmentsSheet` → `TumbaRepository.deleteAttachment`).
- **Локалізація діалогів підтвердження**: тексти в `TumbaViewModel` («Delete Forever?» тощо)
  досі англійською, хоча решта інтерфейсу — українською. Потрібен `when` по типу дії + рядки
  в `TumbaStrings`.
- **Множина для лічильників**: `"1 нотаток"` замість `"1 нотатка"` — потрібні окремі ключі
  для 1/2-4/5+.
- **Календар**: місяці й дні тижня завжди `Locale.getDefault()`, тому перемикання мови в
  налаштуваннях на нього не впливає; тиждень показує лише перший рядок місяця.
- Дрібне: 32 ключі в `TumbaStrings` не використовуються; `GraphNode` у графі знань — мертвий
  клас; у налаштуваннях свотчі акцентів у світлій темі показують темну палітру.

## Перевірка

Компіляцію тут виконати неможливо: на машині немає JDK, Gradle і платформ Android SDK, тому
всі зміни — статичний рев'юз із перевіркою зв'язності (символи, імпорти, кількість полів у
`TumbaStrings`: 217 полів × 3 мови). Перший `./gradlew assembleDebug` в Android Studio —
обов'язковий крок перед встановленням.
